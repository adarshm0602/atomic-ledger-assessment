# Assumptions

1. **Scope:** Only the excerpt supplied in the request is available. It specifies an API, so the deliverable is a backend with interactive Swagger/ReDoc interfaces. Earlier sections may add requirements that would need to be reconciled. The bonus transfer API is implemented.
2. **Account creation:** Accounts start at zero. Fund them through a credit transaction. Account names need not be unique. Account deletion and manual balance edits are not exposed.
3. **Currency:** All accounts use a single unspecified currency with two decimal places. There is no currency conversion, fee, interest, or overdraft. The minimum positive amount is 0.01. Maximum amount and maximum account balance are 999999999999.99.
4. **Amounts:** Requests accept JSON numbers or decimal strings; strings are recommended for clients that otherwise round JSON numbers. Values must be finite, positive, and exactly representable in cents. Trailing zeroes and scientific notation representing a valid cent amount are accepted; fractional cents are rejected rather than rounded. Responses always use decimal strings with exactly two places. The JSON parser preserves numeric decimal precision.
5. **Identifiers:** IDs are positive signed-64-bit integers. JSON body IDs must be integer values, not strings, decimal numbers, or booleans. Path IDs must contain positive base-10 digits without leading zeroes. Valid but nonexistent IDs produce 404; malformed IDs produce 422.
6. **References:** `reference_id` is required and is a case-sensitive string of 1–128 characters after surrounding whitespace is removed. Names are trimmed and limited to 1–100 characters. A reference is unique per account, regardless of credit/debit type or amount. Different accounts may reuse a reference for independent transactions.
7. **Duplicate behavior:** Any duplicate reference on an affected account returns 409, even if the repeated request has an identical payload. A successful operation is never silently repeated. For a retry after a lost response, 409 means the reference is already used; inspect that account's history and compare the recorded type and amount. No automatic replay of the original response is implemented.
8. **Transfer references:** One transfer creates two ledger entries with the same reference, one on each account. The reference must therefore be unused on **both** accounts, including by previous standalone transactions. This intentionally shares the same uniqueness rules across standalone transactions and transfers. A collision on either leg rejects the whole transfer. Self-transfers are rejected with 422.
9. **Status codes:** Creation returns 201; reads return 200. Malformed JSON returns 400, unsupported content types 415, invalid fields/pagination 422, missing accounts 404, duplicate references/insufficient funds/balance capacity 409, transient database contention 503, and unexpected failures 500. Error bodies share a single envelope.
10. **Pagination:** `page` starts at 1; `page_size` defaults to 20 and is bounded at 100. Maximum page is 1,000,000,000. Query integers cannot use signs, decimals, scientific notation, whitespace, or leading zeroes. Unknown pagination query fields are rejected. Pages beyond the last page return an empty array; empty lists have zero total pages. Results are newest ID first. Pagination uses offsets, not a cross-request immutable snapshot.
11. **Database:** SQLite runs on a local filesystem and serializes writers. Each request uses a separate connection; correctness does not depend on a process-local mutex. There is a five-second database-lock timeout. For distributed replicas or greater write throughput, database topology and concurrency design would need to be revisited.
12. **Durability boundary:** Atomicity is guaranteed for operations through the API and its database transactions. Administrators who write directly to database tables can bypass service-level ledger consistency rules. Constraints enforce individual row/reference integrity; they do not independently reconstruct account balances from ledger sums.
13. **Ledger semantics:** A standalone credit/debit represents an external adjustment to the tracked balance, with no external settlement integration. Transfers conserve the combined account balances and record both legs. Records have UTC timestamps and are immutable through the API; there are no update/delete endpoints.
14. **Access:** This is a local assessment with no authentication, authorization, users, tenant isolation, or CORS configuration. It binds to loopback in the documented command. Those features are outside the supplied requirements.
15. **Invalid requests:** Unknown JSON fields are rejected. Duplicate JSON object keys, nonstandard JSON `NaN`/`Infinity`, and malformed syntax return 400. Missing bodies and valid JSON of the wrong shape return 422. No request can supply an opening balance.
16. **Schema management:** Startup creates version 1 tables and indexes if missing. Versioned upgrade migrations, production backup automation, and import of preexisting schemas are outside this submission.
